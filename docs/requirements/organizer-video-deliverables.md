## 1. Overview & Intent

This is a **hiring hackathon** — the organizers are actively recruiting developers to join their team. The emphasis is explicit:

- **It is *not* about coding fast.** It is about approaching the chosen problem statement thoughtfully and then designing **scalable, well-structured, and clear code**.
- It is a chance to **showcase development skills and logic**.
- They are looking for someone with **solid technical skills, logical thinking**, and the ability to **work on real-world, dynamic projects**.

## 3. Hard Requirements & Constraints

### 3.1 Data & Backend
- **Model your data well** — database design is highly valued.
- Use **local databases (MySQL / PostgreSQL)**.
- **Do NOT rely on Backend-as-a-Service platforms** — explicitly named to avoid:
  - Firebase
  - Supabase
  - MongoDB Atlas
- **Build from scratch with minimal third-party APIs.** Fewer dependencies means your project won't break when a third-party platform has bugs or outages.

### 3.2 Data Behavior
- **Use real-time and dynamic data.**
- **Static JSON is acceptable for quick prototyping only — NOT for the final solution.**

### 3.3 Robustness
- **Robust input validation.** User errors must be handled gracefully.
  - _Example:_ if a user enters an invalid email, they must receive feedback that the entered email is invalid.

### 3.4 Version Control
- **Proper use of Git.** One member managing the GitHub repo is **not** enough — the whole team must contribute.

### 3.5 UI / UX
- **Interactive and clean UI** — the interface is "the face of your project."
- **Consistent color schemes and layout.**
- **Intuitive navigation** — menus that make sense, with proper spacing and flow.

### 3.6 Technology Choices
- **Trendy tech (AI, blockchain, chatbots) is welcome — but only if it genuinely adds value** to your solution.
- **Understand the tools you use.** Don't just copy and paste code; understand *why* tools are used and *what* they do.

## 4. Evaluation Criteria — How You'll Be Judged

The reviewers will assess:

- Coding standard
- Logic
- Modularity
- Front-end design
- Performance
- Scalability
- Security
- Usability
- Debugging skill
- **Database design** — *called out as the most important*

They will **also** look at:

- Your **approach to the problem statement**
- **Modular architecture**
- **Coding pattern**
- **Attention to detail**

> Closing reminder from the organizers: *"We are here to hire good developers, so try to impress your reviewers with good technical skills."*
